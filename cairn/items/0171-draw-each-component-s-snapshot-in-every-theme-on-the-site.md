## Problem

Snapshots in the metadata are drawn with the default theme. The ascii theme in
particular is a selling point; a component page should show it.

## Acceptance criteria

- [x] The metadata carries the draw arguments, not only the text, so the site can redraw a snapshot per theme
- [ ] A component page switches its snapshots with the theme switcher

## 2026-10-03

The metadata carries each theme's drawing rather than the draw arguments: a .meta.ts writes a snapshot as draw: (glyphs) => string, and assembling the metadata draws it with every theme's Glyphs, keeping text (default) and adding themes: {name: text} for the themes that draw it differently (today ink, rounded, and phosphor, double; every other theme draws single like the default). meta.json stays plain data, so llms.txt and the MCP server carry it too, and a consumer needs no function registry to redraw. Snapshots that show one set on purpose (every border set, under ASCII) stay fixed text. On the page, each distinct drawing is a Painted in a wrapper marked data-rk-theme-only with the themes that draw it; tokens.css, generated by finish-css.ts, hides any element whose nearest data-rk-theme context it does not name (default = no context), with no script, and nested contexts defer to the inner one. The no-JS test reads only visible figures, and a new test stamps data-rk-theme on <html>, as 0148's switcher will, and checks every component's visible snapshots against themes[theme] ?? text. Criterion 2 is built to the switcher's contract (agreed with site: data-rk-theme on <html>) and ticks when 0148 lands. No shipped theme draws ASCII, though the problem statement calls the ascii theme a selling point: an ASCII preset would show here with no further work.
