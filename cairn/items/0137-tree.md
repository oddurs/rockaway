## Purpose

A hierarchy you can expand and collapse: a file tree, and the site's
navigation. Rows behave like List rows (cursor, reverse-video selection,
type-ahead); depth is drawn with tree guides (`├─ └─ │`) from the junction
table, so the guides are geometry, not text. Not for flat collections (List)
or menus (Menu).

## Anatomy

`<Tree>` and `<TreeItem title>` on React Aria's `Tree`. Each row: guides, the
expand mark, the cursor cell, the label. Items may be links (`href`), which is
how the site's navigation pane uses it.

## States

`data-expanded`, `data-focused`, `data-selected`, `data-disabled`, `data-level`.

## Tokens consumed

`fg.default`, `fg.muted` for guides, `bg.inverse` / `fg.on-inverse` for selection.

## Accessibility

`treegrid` semantics from React Aria: arrows move, right expands, left
collapses or moves to the parent, type-ahead, Home and End. Guides and marks
are `aria-hidden`; level, expanded state and position in set are announced by
the role.

## 2026-10-03

Guides are geometry: treeGuides builds each row's buffer with addEdges, two cells a level (an ancestor's north+south while it has siblings to come, then the row's tee or corner and a horizontal, and for a leaf one more horizontal through its expand cell, so a leaf reads ├── and a branch ├─▾). Lineage comes from React Aria's collection inside TreeItemContent, as the handbook's collection note says: the row's level, and for it and each ancestor whether a next sibling of type item exists (the walk React Aria's own Collection uses). The guides render as the painter's runs (rowRuns) in a span marked data-rk-painted with Tree's painter prop, so the cell renderer strokes them like any painted chrome and continuity checks them. Guides stay light in heavy and double themes, rounded where the theme rounds, ASCII in ASCII.

## 2026-10-03

Row order is cursor, check (multi-select), guides, expand, air, label. The cursor is first, where List puts it, not beside the expand mark as the ticket's anatomy listed: in the default theme mark.cursor and mark.collapsed are both the same glyph, and only their place tells them apart. The expand mark is React Aria's chevron button (slot chevron), so it expands and never follows a row's href, and React Aria names it; the glyph inside is aria-hidden. Links: a RouterProvider in the story records navigation (the tester page's base target would otherwise navigate the runner away); a press and Enter on link rows navigate, the chevron press does not. Type-ahead: a space straight after typing is read as part of the search, so the walkthrough selects with Enter. Empty mark cells needed block-size: a cell, or align-items centred them half a row down and conformance caught it. Long titles: text-overflow ellipsis in the DOM (Chromium has no string text-overflow, so the DOM ellipsis is the font's even under ASCII); treeBuffer cuts with the theme's.

## Result

Tree on React Aria's Tree: List's rows, guides as junction-table edges two cells a level, chevron expands without navigating, href rows navigate.
