## Purpose

The selection primitive a TUI leans on: a cursor, reverse-video selection,
type-ahead, and a viewport that scrolls in whole rows.

## Acceptance criteria

- [x] Cursor glyph plus reverse video, so selection survives forced colors and colour blindness
- [ ] Virtualised by row, and the scrollbar is drawn in cells
- [x] Keyboard: arrows, home and end, page keys, type-ahead

## TUI criteria (added by the pivot, cairn 0076)

- [x] Sized in cells, and drawn by the frame engine: no box characters written by hand
- [x] Frame glyphs are `aria-hidden`; the accessible name never contains one
- [x] Ships a text snapshot, which is its documentation as much as its test
- [x] Operable by keyboard alone, and usable with a finger at touch density
- [x] State reads without colour: an attribute or a mark carries it too
- [x] Conforms at `strict`, or declares its exception with a reason

## 2026-09-23

Selection is two signals, never one: a cursor glyph in its own cell and reverse video. Either alone is a single point of failure — the glyph is lost to a reader who cannot see it, the reverse is lost to a forced-colors mode that reverses everything. The cursor is aria-hidden, because '▸ src/index.ts' is not the name of anything.

## 2026-09-23

The scrollbar is a one-cell column drawn by the engine, so it snapshots as text and its whole behaviour fits in five lines: thumb at the top, thumb walking down, thumb at the bottom, full thumb when there is nothing to scroll, and one cell minimum however long the list. It takes a row count rather than the DOM, which is what will let 0115 virtualise underneath it without touching it.

## 2026-09-23

Virtualisation is NOT done, and its criterion is left unticked rather than reworded: it moved to 0115 with everything learned. React Aria's Virtualizer does virtualise, but a keyboard jump to an unrendered row (End, or type-ahead across a long list) leaves focus nowhere. Correct keyboard behaviour is the point of a TUI list, so the Virtualizer came out and the rows all render for now. Ruled out along the way: scroll-snap, an onScroll prop shadowing the virtualiser's own handler, and static versus dynamic collections.

## 2026-09-23

A grid item that scrolls needs grid-template-rows: minmax(0, 1fr) and min-block-size: 0. Without them the row takes its height from a thousand list rows, the box never scrolls, and — while the Virtualizer was still in — it saw every row as visible. Worth remembering for any component with a viewport.
